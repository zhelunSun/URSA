## 比较条件和最小规模

首轮只准备两个条件：U = 当前 URSA；G = 同一模型客户端与两个相同工具的单 Agent 循环。
G 尚未实现，不把它称为已接通的通用系统。G 不必输出 URSA 计划、角色 JSON 或遵循其 eligible-node 策略。
共享工具边界负责资源许可、类型、输入 hash 和输出核验；若这些共同约束消除了某种差异，就如实解释比较范围。
完整通用代码 Agent 留作另一个整体系统参照，当前不安装，也不混入受控比较。

知识条件固定 K0 = unavailable，两边完全一致。因此首轮只能评价已有工具组织与交付行为，不能比较知识效果。
模型沿用已授权的 `deepseek-ai/DeepSeek-V4-Flash`、SiliconFlow、thinking=false、temperature=0、top_p=1、
max completion=4096、SDK retries=0、cache=false。后续实际准入时保存精确 endpoint/config/提示 SHA。
建议首次开发小样是 3 任务 × 2 条件 × 1 次 = **6 episodes**，每例 12 模型决策/10 工具调用/600 秒/70,000 recorded tokens。
全部角色与服务内部调用计入总量；合计最多 72 决策。token 检查有最后一次响应超限可能，不能称扣费硬上限。
先保留零调用的准备回执；上述只是下一次入口可复用的预算设计，本轮未启动六例。

两边各允许最多一轮同等开发反馈修订，修订前的失败不得覆盖；修订形成新配置版本，开发结果不与旧版本混算。
首次每例一遍只能发现接口问题；正式系统比较需另选未调试任务、固定参考与重复策略后再确定样本量。
同产品缺资源/改问法不形成三个独立空间样本；本阶段不估计显著性或方法效应。

## 外部评分与失败处理

- 正常任务：同时满足交付、预定数值正确性、产品一致性与解释边界才计完成。整数计数逐项精确；比例按上表容差。
- 不应完成的任务：正确澄清/停止单独统计。仅说“无法完成”但未识别缺失信息不自动满分。
- 严重无依据断言：编造科学依据、把树类当验证生境、把像元分母当行政区面积；独立列出，不被漂亮图件抵消。
- 地图一致性、数值质量、依据适用性、过程可追溯性分列。不能用是否生成 URSA trace 给主任务正确性加分。
- 记录模型/工具调用、tokens、wall time、人工介入、费用（无账单则 null）；基础设施错误保留分母并单列。
- 保留全部首错；重跑必须新 ID、原因和配置 SHA；原记录不可回填。正式参考不根据已观察结果追改。

公共任务投影不包含 evaluator_only、旧计划、产物答案、轨迹或本地源路径。接入层另管理物理资源绑定。
`public/` 与 `private/` 是文件组织边界，**不是操作系统隔离**；不允许把整个准备目录/仓库挂给自由代码 Agent。
目前 public packet 仅列工具名，尚不是完整可执行工具接口；后续要补相同 schema/说明/反馈与资源解析入口，
并证明双方看到的字节与许可相同。未来被测进程不读取生成任务包时使用的旧 state。

## 知识接线预留

`ExpertsRS/knowledge_port.py` 提供版本化 request/response、Protocol 和 `UnavailableKnowledgePort`。
请求预留问题、适用范围、产品/知识证据 ID 与 SHA、委托模型/工具预算；返回预留答案、适用条件、限制、
源 run ID、分类证据及嵌套用量。不可用/失败不能携带已支持答案；错 request ID 和隐匿超预算调用会被拒绝。
这些只是传输结构检查，引用 SHA 的格式正确不等于文件已核验，更不等于科学蕴含成立。

**当前端口由准备脚本调用，尚未注入 ExpertsRSSystem 的模型上下文或改变动作。**
接口返回明确 unavailable、零模型/工具调用；不会生成占位知识答案，不把说明文字包装成第二章推理。
第二章就绪后再接真实 service，验证证据文件、来源适用性与全部用量；随后将响应传给决策角色并记录采用/拒绝原因。
此时再开 K1 知识可用条件，并补知识可获得、被调用、改变决策、判断正确四个层次的验证。
