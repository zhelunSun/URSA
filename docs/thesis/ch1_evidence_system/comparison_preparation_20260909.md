# 通用 Agent 比较：接线与评价准备建议

日期：2026-09-09。状态：待任务与预算冻结的设计草案；未安装对照框架、未运行模型、未接受科学协议。
所属：第三章系统构建与应用验证的准备，不建立独立 benchmark 贡献，也不重复第一章机制实验。

2026-09-10 已具体化为 [09-10 知识接线预留与验证设计](validation_design_20260910.md)：三项开发任务、K0 知识不可用、U/G 条件与无 API 准备回执；G 尚未实现。

## 两种问题不能用一张排行榜回答

| 对照层次 | 配置建议 | 能回答什么 |
| --- | --- | --- |
| 受控比较 | URSA 与一个明确实现的单 Agent 工具循环；尽量固定模型版本、工具实现、数据、知识可见性、预算与提示调试机会 | 在此条件下，运行组织和领域集成是否带来差异；仍需通过局部消融才能归因具体机制 |
| 系统应用参照 | URSA 与一个可运行的通用代码 Agent，如配置好的 OpenHands；Claude Agent SDK 等作为另选 | 用户把相同公开任务交给不同完整系统时的表现。若模型/权限/默认上下文不同，只能解释整体系统表现 |

LangGraph、AutoGen、Agents SDK 是构建组件，必须写出具体 agent loop、提示、工具与停止规则，才是可复现对照。
首轮建议只接 **一个受控对照**；可优先复用现有模型客户端并写清简单工具循环，之后再接一个现成系统作外部参照。
若直接使用完整通用 Agent 的同模型配置作为受控对照，必须先证明工具权限、知识与预算条件确能对齐。
目前未核查具体版本/安装兼容性，不把候选写成已选定或已接入。

## 共同输入与交付合同

1. 公共输入：原始用户问题、资源 ID/类型/年份/许可目录、工具说明、可查询知识及其来源。不给 URSA 专用计划答案。
2. 共享工具条件：同一确定性工具实现、参数语义、返回事实与错误。输入/输出校验留在公共工具边界，
   不强制对照使用 URSA 的计划图、角色 JSON、eligible-node 控制或恢复策略。
3. 自由编码另成条件：如允许 shell/自行实现算法，两边须给予相当的包、算力、文件与网络条件；
   否则将权限差异列为系统配置，不混入同工具因果比较。
4. 结果只要求通用交付：回答、数值及单位/分母、产物、可定位的依据、适用范围、不可用/停止原因。
   使用无损适配映射对照原生输出，不自动补数值/引用、不替对照修计划；格式错误本身保留。
5. 评价在系统外：结果内容是否正确由预定参考核验，不用“是否生成 URSA trace/checkpoint”给 URSA 加分。
   轨迹完整性可以独立记分，但不能代替结果质量。知识解释需要来源与适用性核验，单纯引用 ID 存在不够。

隔离方式需要实际落地：只向被测进程开放专用输入/工具目录；禁止挂载整个第三章仓库或 URSA 证据目录，
以免 reference.json、任务评分脚本、历史日志和 Git 历史泄漏答案。只在 prompt 里要求“不要读答案”不算隔离。
当前同进程 local executor 不构成自由代码沙箱；开放任意代码之前先验证容器/进程权限边界。

## 三类开发检查，暂不算正式任务集

| 检查 | 可观察行为 | 当前限制 |
| --- | --- | --- |
| 既有产品描述 | 原网格组成、同源图、分母与适用边界 | S1 已有离线链；单独这一任务太简单，不足以检验知识协同或系统价值 |
| 依据影响解释或计算 | 知识证据与观测/产品一起决定采用哪种计算或哪些结论不能给出 | 第二章接口与北京任务知识覆盖待核，不编造已有能力 |
| 不完整/不兼容输入 | 有针对性的澄清、停止或获准修正，保留首错和原始输入 | 不按某一系统内置错误字符串量身出题；修复条件和可用动作对齐 |

开发检查用于找协议缺陷；正式测试应另留未用于调试的任务/变体，知识与参考由研究者核定。
重复同一北京产品只能检验输出稳定性，不能当作增加独立空间样本。

## 运行前应固定的项目

- 系统/模型/工具/知识/输入版本；系统提示和允许的提示优化次数；模型采样设置及可记录的 seed。
- 每个系统的总工具和模型预算，包括全部角色、重试与子 Agent；相同 token 上限也不等于相同货币成本。
- 超时、取消、格式失败、权限拒绝、受控停止、澄清、基础设施错误的分类，以及哪些任务本来允许澄清/停止。
- 外部评价标准、数值容差、空间/专题质量指标、解释核验方式、开发集与测试集区分。不能从看到的结果反定标准。
- 原始输出不覆盖；首错与所有尝试保留；复跑明确原因和新编号；记录人工介入，不事后只选最好一轮。

## 分开报告的结果

任务完成且满足预定正确性要求的比例；不应完成任务中的正确澄清/停止；结果数值/空间/专题质量；
知识依据有效性与适用性；产物/回答一致性；耗时、实际模型调用、token、可核实费用和人工介入。
缺乏账单/可靠定价时费用留空，不把 token 当货币。基础设施失败单列并保留原始分母，禁止悄悄剔除。

不能用 15/15 历史 evaluator closure 或 136 项测试作为第三章成功率。不能用同源算法的北京计数一致证明专题精度。
若通用 Agent 已能很好完成简单组成任务，应把结果诚实保留，并检查真正需要知识/多产品协同的任务是否有差异，
而不是削弱对照权限或追加不对等提示。
