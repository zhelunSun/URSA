## 科学表达规范

- 图内优先使用稳定中文概念；首次在正文或图注给出英文术语。代码类名、JSON 字段、具体框架名只进
  方法实现或附录。
- 实线箭头表示任务、控制、数据或反馈流，虚线仅表示只读评测或隔离测试关系；每一类箭头在同图中
  保持一致。
- 模块图、角色图、运行机制图和系统外评测不能混为同一层级。runtime 不是 Agent，evaluator 不参与
  被测运行。
- 颜色只用于区分对象类别，不能替代证据强度。绿色不等于“科学正确”，红色不等于所有失败；应通过
  图注和正文说明终态语义。
- 使用低饱和蓝（Brain）、青绿（Data）、浅橙（Tools）、紫灰（runtime/control）和中性灰
  （evaluation）。保持白底、深灰边框、无渐变、无阴影、无产品 Logo。
- 论文版字体优先思源黑体/微软雅黑与 Arial；最小文字不低于 8 pt。PPT 从 SVG 放大，不从低分辨率
  位图放大。

## 图注边界模板

每张图的图注应同时包含“图展示什么”与“图不证明什么”。例如：

> 图 X 展示 URSA 领域智能体运行时中计划、执行事实和交付义务的控制关系。该图描述系统机制；
> v0.5.3 的小规模集成运行支持其协议闭合，不单独证明规划质量提升、专题精度或生产级恢复能力。

## 可重复渲染

1. 保持 `src/` 文件与 `../module_continuity_map.md` 的 Mermaid 代码语义一致；修改语义时先改主源，
   再同步本目录。
2. 使用 PowerShell 7（`pwsh`）运行；图源和脚本采用 UTF-8，不使用旧版 Windows PowerShell 5.1：

   ```powershell
   pwsh -NoProfile -File .\render.ps1
   ```

3. 脚本固定 Mermaid CLI 版本，优先使用 Codex bundled Node，并探测 Chrome/Chromium；渲染到 `out/`。
   SVG 是论文/PPT 主格式；PNG 从同一渲染结果生成并写入 300 dpi 元数据。
4. 每次渲染后人工检查：中文字体无乱码、箭头未截断、虚线可见、图号对应正确、图中没有新增未经
   证据支持的结论。记录输入与输出的 SHA-256。

当前输出已经验证渲染链路和 300 dpi 元数据；`CH1-FIG-02` 是横向责任链，适合论文通栏或 PPT，
`CH1-FIG-03` 适合论文通栏。排版定稿时仍须在 Word/PPT 实际版面检查字号，不能只以像素尺寸判断。

若当前机器缺少 Node、Chrome/Chromium 或无法取得固定版本 Mermaid CLI，脚本应失败退出而不创建
`node_modules`、不污染仓库根目录；此时仅提交图源与脚手架，待受控环境渲染。
