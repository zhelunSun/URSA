# 阶段目标：复用 URSA 的北京产品描述链

日期：2026-09-09。研究者授权在既有 runtime/工具架构上推进，并检查潜在问题。
分支：`codex/ch3-domain-toolchain`；起点 `cedeb960f424f3d7547377818f803349700e00ac`。
软件开发版本：`0.5.4.dev0`，不是新方法版本、论文效果接受或 v0.5.3 历史实验重跑。

## 本阶段要交付什么

同一 `ExpertsRSSystem.run` / CLI，通过显式 `classification-v1` 配置，消费研究者指定的既有
八类分类产品和 AOI，形成原网格组成统计、同源地图、产物引用报告、计划图和事实过程图。
只做 scripted-offline 工程贯通；没有真实模型自主规划、第二章知识推理或第三章系统比较。

研究贡献安排沿总控现有提纲：第一章研究需求/规划/反馈/恢复的方法，第三章复用这些机制，
接入领域数据和专题能力。代码仍由同一 runtime 管理，不创建第二个调度器。

## 有界改动

- 默认工具注册表保持 18 项；新配置显式加入两个工具，运行时只开放组成统计与地图两个动作。
- 扩展现有 request/graph 输入：调用方绑定 `classification` 与 `study_area`；路径和 hash 留在运行时。
- 模型决策接口只收到逻辑资源 ID、类型和年份，不收到路径或外部参考答案。
- `composition_table` 与 `aoi` 是明确类型；任务、节点、参数、依赖仍经过既有 validator 与执行准入。
- 实际计算从第三章参考脚本适配，去掉 intake、参考读取和参考写回；原网格、类别、nodata 与 AOI 语义不变。
- 报告值取自执行产物，评价参考由外部核验步骤读取，不能进入任务输入或 provider context。
- 原环境不加新依赖；集成环境 `.venv-domain` 从旧环境冻结包构建，再加 domain extras。

## 已定位的潜在问题与处理

| 问题 | 本阶段处理 | 验证方向 |
| --- | --- | --- |
| 底层 graph 支持多输入，但上层只绑定首个 raster | 显式资源绑定与类型核对 | 资源错标、越权目录、输入 hash 漂移 |
| 旧工具按 `success` 推进，输出文件缺失也可能被登记 | 验文件存在、非空、本 action 路径、hash；失败保留 rejection | 假成功、外部文件冒充、输入/中间产物被改写 |
| `get_tool_by_name` 可返回模块中的非公开 helper | 查找限定在公开函数集合 | 默认 18 名称和 helper 拒绝 |
| 报告引用只核对 ID 存在，未要求对应事实支持 | 交付引用必须匹配 factual deliverable，报告前重验产物 hash | 引用错误、报告前产物漂移 |
| NDVI 专用提示和 checkpoint 不适合直接当通用领域智能体 | 本阶段显式标 scripted profile；领域恢复和 live 接入未启用 | 禁止静默进入 live；原机制回归保留 |

仍保留的工程限制：本地进程内同步工具运行，墙钟预算不等于可以抢占底层 C/Python 计算；
不是进程沙箱或 crash recovery；读取时的身份检查不能充当操作系统级并发不可变保证。
这些不以新增类名或配置文件伪装成已解决能力。

## 验收与停止点

1. 原有 121 项回归、M1/D2 no-API closeout 通过，默认工具与旧 evaluator 条件不扩张。
2. 小栅格边界、空有效域、类别/CRS 错误、输出冒充、源/产物篡改等定向检查通过。
3. 既有北京输入/AOI hash 匹配；新 run 不覆盖历史或第三章参考目录。
4. 新 run 的八类整数计数、有效/nodata 总数和比例与外部冻结参考逐项核对；该比较只证明同一产品计算一致。
5. 地图按科学图件合同生成 PNG/SVG，执行确定性审计及实际 PNG 查看。
6. 提交推送到独立开发分支，保留 v0.5.3 活动基线与保护标签；不自动合并或变更科学口径。

本阶段完成后，下一步是对照第二章真实求解接口补齐知识调用，并为 live domain 运行设计独立小样；
森林对象与格局任务需先明确领域口径和可调用工具。历史 5×3 包继续从 laptop 恢复，不伪造替代。
