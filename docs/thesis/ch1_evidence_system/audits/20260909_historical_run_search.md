## 可直接执行的恢复核验

在发现候选目录后，从当前仓库运行：

```powershell
python scripts/check_v053_evidence.py --root '候选目录/ExpertsRS/results/ch1_d3_light'
```

该脚本只读文件并输出四项匹配结果；不修改候选目录。
退出 0 表示四个索引文件匹配，退出 2 表示有缺失、不可读或 hash 不匹配。
即使四项匹配，也只证明索引文件身份，尚未证明完整 trial 包已恢复。

接下来的恢复顺序：

1. 根据原机器/备份线索定位完整目录，先原位计算 hash，保留来源位置。
2. 对命中包复制至新建的恢复暂存目录，禁止覆盖正式目录或改写 manifest。
3. 检查包内 manifest 所列相对文件及 hash、15 槽位、trace/产物引用，以及失败运行包；
   缺件逐项记录，路径先做包含性检查，不盲读外部绝对引用。
4. 拷贝后复核 hash；只有已核对的对象才更新证据可用性状态，并明确仍缺的部分。

下一步在 laptop 上定位 `ExpertsRS/results/ch1_d3_light`，保留整个目录（包括失败轮次），
而非只复制四个摘要 JSON。上述检查脚本可在 laptop 或拷贝后的新目录运行。
恢复未完成不阻塞代码开发和当前只读接口准备，但阻塞“历史原始包已重新核验”的表述。
