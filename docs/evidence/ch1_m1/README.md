## ReAct trace invariant

The scripted pilot performs four real local tool calls:

1. Scientist: `list_available_data_files`;
2. Scientist: `read_raster_metadata`;
3. Engineer: `calculate_ndvi`;
4. Engineer: `apply_threshold`.

Each recorded `tool_call` now updates the same counter used by routed LLM tool
calls. The final trace must report `Scientist=2` and `Engineer=2`; the pilot
fails if this invariant is not met. This resolves the earlier diagnostic defect
where the events existed but the scripted path reported both counters as zero.

## Evidence classification

| Evidence | What it checks | What it does not establish |
| --- | --- | --- |
| Unit/regression tests | Contract coverage, validator/repair logic, routing, budgets, trace counters | Scientific performance or generality |
| Deterministic repair/stop traces | Inspectability and conservative local behavior | LLM planning improvement |
| Scripted no-API real-tool pilot | Real raster integration, semantic band provenance, nodata invariants, observation sequence, artifact and trace production | Threshold/thematic accuracy or autonomous LLM planning reliability |
| `react_demo.py` | Credentialed real-LLM execution surface | A completed or evaluated experiment |
| Future matched P0--P3 study | Incremental effect of structure, validation, and repair | Not part of this M1 closeout |
